# hwp5 — 의존성 없는 HWP 5.0 리더 / 최소 변경 에디터

관공서 서식은 대부분 HWP다. 그런데 `olefile`조차 설치할 수 없는 폐쇄망·컨테이너
환경에서 서식을 채워야 하는 상황이 실제로 있었다. 이 패키지는 그때 표준 라이브러리만으로
직접 만든 것이다. 외부 의존성이 하나도 없다.

```python
import hwp5

print(hwp5.extract_text("서식.hwp"))          # 본문 텍스트 추출

result = hwp5.fill_form(                       # 서식 채우기
    "서식.hwp", "제출본.hwp",
    {"핵심내용 3줄 이내 요약": "○ 첫 줄\n  - 둘째 줄"},
)
assert not result["missed"]                    # 매칭 실패한 key 확인은 필수
```

## 설계상 중요한 선택

**컨테이너를 다시 쓰지 않는다.** CFB 라이터를 처음부터 구현해서 항등 왕복 테스트까지
통과시켰지만, 그렇게 만든 파일을 한글이 열지 못했다. 명세를 지켜도 한글이 받아들이지 않는
지점이 있다는 뜻이다. 그래서 방향을 바꿔 **원본 바이트를 보존하고 파일 끝에 섹터를 덧붙인 뒤
FAT과 디렉터리 엔트리만 패치**한다. 실제 서식 파일로 검증했을 때 원본 영역에서 바뀌는 바이트는
33개뿐이었다. 건드리지 않은 것이 많을수록 열릴 확률이 높다.

## 직접 부딪혀 알아낸 것들

**모든 PARA_TEXT는 문단 끝 문자 `0x000D`로 끝나야 한다.** 원본 50개 문단을 전수 확인해서
찾아낸 규칙이다. 이걸 빠뜨리면 한글이 파일을 열지 못한다.

**PARA_HEADER 필드 오프셋.** 문서마다 설명이 엇갈려서, 선언된 개수와 실제 레코드 크기를
대조하는 방식으로 직접 확정했다. `nChars@0`, `nCharShapes@12`, `nRangeTags@14`,
`nLineSegs@16`. `@14`를 nLineSegs로 착각하고 1을 쓰면 한글이 존재하지 않는 range tag를
읽으러 가서 파일이 깨진다.

**LINE_SEG은 절대 건드리지 않는다.** 줄 나눔 정보를 새 텍스트에 맞춰 다시 계산하려고 했다가
파일이 깨졌다. 한글이 열 때 알아서 다시 계산하므로 그대로 두는 것이 맞다. 텍스트만 바꾸고
LINE_SEG을 손대지 않은 버전은 정상적으로 열렸다.

**CHAR_SHAPE 구간은 하나로 합쳐야 한다.** 원본 제목 문단은 ①②③ 위첨자 때문에 글자모양이
8개 구간으로 쪼개져 있었다. 텍스트만 갈아끼우면 그 위첨자 서식이 새 글자의 엉뚱한 위치에
그대로 걸린다("전기"의 기, "학습"이 위로 뜨는 현상). 위치 0의 shapeId 하나로 통일해야 한다.

**미니스트림 임계값 4096.** 이보다 작은 스트림은 미니FAT 경로로 읽히기 때문에 일반 섹터에
써두면 판독 불가가 된다. 0으로 패딩해 임계값을 넘긴다 — raw deflate는 뒤쪽 0을 무시하므로
압축 해제 결과는 동일하다.

## 파일 구성

`cfb.py` — MS-CFB 리더. FAT/DIFAT/미니FAT 체인 순회와 디렉터리 엔트리 파싱.
`records.py` — BodyText 레코드 파싱·직렬화, 문단 텍스트 인코딩, 헤더 필드 갱신.
`container.py` — 섹터 덧붙이기 + FAT·디렉터리 패치 방식의 스트림 교체.
`__init__.py` — `extract_text`, `fill_form` 두 개의 상위 API.
